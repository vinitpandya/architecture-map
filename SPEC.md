one phase at a time, verifying each phase against **§14** before starting the
next.

Three standing rules:

1. **You do not have the real service repositories.** Everything is built and

## 1 · Product definition

A local-first map of a team's service estate. It answers, with citations:

- What services exist, and what does each one own?
- Who produces and who consumes a given Kafka topic?
- What calls this service, and what does it call?
- Which services share a contract, and are they on the same version?
- Where in the code is any of this actually true?

It is built from **manifests** — JSON files conforming to
`schema/manifest.schema.json`, one per repository, produced by scanning that
repository. The app never scans anything itself; it ingests manifests that
arrive in `inbox/`. How they got there is deliberately not its business.

### In scope for v1

Layer A (topology) end to end: ingest, link, drift detection, graph, detail
pages, text search, and a demo estate to prove it all works.

### Explicitly out of scope for v1

Do not build these. They have dedicated phases later and building them now will
make the MVP late and wrong:

- Layer B process flows (tables are created in §4; no UI, no API).
- The widget/dashboard system (`Grid.tsx` stays untouched).
- AI/semantic search. Text search only.
- Any form of authentication.
- Any automated invocation of Claude. The app *renders* prompts; a human runs them.

## 3 · Data model

### The two layers

**Layer A — topology.** Services, topics, databases, caches, endpoints,
contracts, externals, and the edges between them. Derived wholly from manifests.
Rebuilt on every ingest. Never hand-edited.

**Layer B — processes.** The L1/L2/L3 process hierarchy and its ordered steps,
each step bound to a Layer A node or edge. Hand-authored. Tables exist in v1;
nothing reads or writes them yet.

**Overrides** are the third thing, and they are what make corrections survive. A
human fixing a description in the UI writes an `overrides` row keyed by node or
edge id. Ingest never touches `overrides`; reads apply them on top of the
derived value. This is why re-scanning cannot eat human work.

### Identifiers

Defined normatively in `schema/manifest.schema.json` under `$defs.nodeId`. Read
it there. The one rule worth repeating: **an id is the wire value, never a human
label**, because two repos scanned in separate sessions must produce a
byte-identical string for the same thing.

Ids contain `:`, `/`, spaces and `{}`. **They must never appear in a URL path
segment.** Every API and every route takes the id as a query parameter:
`GET /api/node?id=...`, `/node?id=...`. Encode with `encodeURIComponent`.

### Edge identity

An edge's stable key is `sha1(from + '|' + kind + '|' + to)`, lowercase hex, as
`edges.id`. This is what an override or a process step points at, so it must not
change when a manifest is re-ingested with the evidence in a different order.

## 4 · Database schema

SQLite via `better-sqlite3`, at `data/architecture.sqlite`. WAL mode, foreign
keys on. Create everything on boot with `CREATE TABLE IF NOT EXISTS`, exactly as
`reference/jira-reports/db.js` does.

```sql
-- ─────────────────────────────────────────────── ingest log

CREATE TABLE IF NOT EXISTS manifests (
  id              INTEGER PRIMARY KEY,
  repo            TEXT NOT NULL,
  commit_sha      TEXT,
  branch          TEXT,
  scanned_at      TEXT,
  ingested_at     TEXT NOT NULL,
  schema_version  INTEGER,
  prompt_version  TEXT,
  producer_kind   TEXT,           -- claude | parser | human
  producer_detail TEXT,
  service_id      TEXT,
  source_file     TEXT,           -- filename it arrived as, if any
  status          TEXT NOT NULL,  -- active | superseded | quarantined
  raw             TEXT NOT NULL,  -- the manifest as received, verbatim
  errors          TEXT            -- ajv errors, JSON, when quarantined
);
CREATE INDEX IF NOT EXISTS manifests_repo ON manifests (repo, status);

-- ─────────────────────────────────────────────── layer A

CREATE TABLE IF NOT EXISTS nodes (
  id            TEXT PRIMARY KEY,
  kind          TEXT NOT NULL,   -- service | kafka.topic | database | cache
                                 -- | endpoint | contract | external
  name          TEXT NOT NULL,
  description   TEXT,
  engine        TEXT,
  method        TEXT,
  path          TEXT,
  contract_type TEXT,
  language      TEXT,            -- services only
  team          TEXT,            -- services only
  owner_repo    TEXT,            -- repo that owns it; NULL when nobody claims it
  orphan        INTEGER NOT NULL DEFAULT 0,  -- referenced but never declared
  first_seen    TEXT NOT NULL,
  last_seen     TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS nodes_kind ON nodes (kind);

-- which manifests asserted this node's existence
CREATE TABLE IF NOT EXISTS node_sources (
  node_id     TEXT NOT NULL,
  manifest_id INTEGER NOT NULL REFERENCES manifests(id) ON DELETE CASCADE,
  repo        TEXT NOT NULL,
  PRIMARY KEY (node_id, manifest_id)
);

CREATE TABLE IF NOT EXISTS edges (
  id          TEXT PRIMARY KEY,          -- sha1(from|kind|to)
  from_id     TEXT NOT NULL,
  to_id       TEXT NOT NULL,
  kind        TEXT NOT NULL,
  contract_id TEXT,
  description TEXT,
  confidence  TEXT NOT NULL,
  repo        TEXT NOT NULL,
  manifest_id INTEGER NOT NULL REFERENCES manifests(id) ON DELETE CASCADE,
  first_seen  TEXT NOT NULL,
  last_seen   TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS edges_from ON edges (from_id);
CREATE INDEX IF NOT EXISTS edges_to   ON edges (to_id);
CREATE INDEX IF NOT EXISTS edges_kind ON edges (kind);

CREATE TABLE IF NOT EXISTS evidence (
  id           INTEGER PRIMARY KEY,
  subject_kind TEXT NOT NULL,   -- node | edge | unresolved
  subject_id   TEXT NOT NULL,
  repo         TEXT NOT NULL,
  file         TEXT NOT NULL,
  line         INTEGER NOT NULL,
  end_line     INTEGER,
  snippet      TEXT NOT NULL,
  manifest_id  INTEGER NOT NULL REFERENCES manifests(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS evidence_subject ON evidence (subject_kind, subject_id);

CREATE TABLE IF NOT EXISTS unresolved (
  id          INTEGER PRIMARY KEY,
  repo        TEXT NOT NULL,
  expected    TEXT NOT NULL,
  raw         TEXT NOT NULL,
  reason      TEXT,
  manifest_id INTEGER NOT NULL REFERENCES manifests(id) ON DELETE CASCADE
);

-- version binding is per SERVICE, never global — two services legitimately
-- bind different versions of the same contract, and that is the finding.
CREATE TABLE IF NOT EXISTS contract_bindings (
  contract_id TEXT NOT NULL,
  service_id  TEXT NOT NULL,
  version     TEXT,
  manifest_id INTEGER NOT NULL REFERENCES manifests(id) ON DELETE CASCADE,
  PRIMARY KEY (contract_id, service_id)
);

-- ─────────────────────────────────────────────── findings

CREATE TABLE IF NOT EXISTS drift (
  id          INTEGER PRIMARY KEY,
  kind        TEXT NOT NULL,   -- see §6
  subject_id  TEXT,
  severity    TEXT NOT NULL,   -- info | warn
  detail      TEXT NOT NULL,
  data        TEXT,            -- JSON payload for the UI
  detected_at TEXT NOT NULL
);

-- ─────────────────────────────────────────────── human corrections

CREATE TABLE IF NOT EXISTS overrides (
  subject_kind TEXT NOT NULL,   -- node | edge
  subject_id   TEXT NOT NULL,
  field        TEXT NOT NULL,   -- description | name | team | hidden | confirmed
  value        TEXT,
  author       TEXT,
  updated_at   TEXT NOT NULL,
  PRIMARY KEY (subject_kind, subject_id, field)
);

-- ─────────────────────────────────────────────── layer B (created, unused in v1)

CREATE TABLE IF NOT EXISTS processes (
  id          INTEGER PRIMARY KEY,
  key         TEXT UNIQUE NOT NULL,
  level       INTEGER NOT NULL,          -- 1 | 2 | 3
  parent_id   INTEGER REFERENCES processes(id) ON DELETE CASCADE,
  name        TEXT NOT NULL,
  description TEXT,
  sort        INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS process_steps (
  id          INTEGER PRIMARY KEY,
  process_id  INTEGER NOT NULL REFERENCES processes(id) ON DELETE CASCADE,
  seq         INTEGER NOT NULL,
  name        TEXT NOT NULL,
  description TEXT,
  node_id     TEXT,
  edge_id     TEXT
);

-- ─────────────────────────────────────────────── search

CREATE VIRTUAL TABLE IF NOT EXISTS search_index USING fts5(
  subject_kind UNINDEXED,
  subject_id   UNINDEXED,
  title,
  body,
  repo         UNINDEXED,
  tokenize = 'porter unicode61'
);
```

## 5 · Ingest

`server/src/ingest.js`. One function, `ingestManifest(json, sourceFile)`, and it
is **idempotent per repo**: re-ingesting a repo replaces exactly that repo's
contribution and touches nothing else.

1. **Validate** against `schema/manifest.schema.json` with ajv
   (`strict: false`, `allErrors: true`, plus `ajv-formats` for `date-time`).
2. **On failure:** insert a `manifests` row with `status='quarantined'`, the raw
   body, and the ajv errors as JSON. Move the file to `inbox/quarantine/`.
   Return the errors. **Do not partially import a failed manifest.**
3. **On success**, in a single transaction:
   - Set `status='superseded'` on all existing `active` manifests for this repo.
   - Delete derived rows for those manifests (`node_sources`, `edges`,
     `evidence`, `unresolved`, `contract_bindings` cascade on `manifest_id`).
   - Insert the new `manifests` row, `status='active'`.
   - Upsert the service as a node (`kind='service'`, carrying `language`,
     `team`, `description`), `owner_repo` = this repo.
   - Upsert every entry of `nodes[]`. Record `node_sources`.
   - For nodes with `kind='contract'` carrying a `version`, write
     `contract_bindings(contract_id, service_id = this manifest's service,
     version)`. **Do not store `version` on the `nodes` row.**
   - Insert `edges[]` with `id = sha1(from|kind|to)`. On conflict, replace.
   - Insert all `evidence` rows for nodes and edges.
   - Insert `unresolved[]`.
4. **Garbage-collect** nodes with no remaining `node_sources` and no referencing
   edge.
5. **Re-run the link pass** (§6) — it is global, cheap, and must run after every
   ingest.
6. **Rebuild the search index** for the affected subjects (§7).

`first_seen` is preserved across re-ingests; `last_seen` is set to now.

### Entry points

- `POST /api/ingest` with a manifest as the JSON body.
- `POST /api/ingest/sweep` — reads every `*.json` in `inbox/`, ingests each,
  moves successes to `inbox/ingested/` and failures to `inbox/quarantine/`,
  returns a per-file result.
- `node server/scripts/validate.mjs <file>` — validate only, no DB. Exits 1 on
  failure and prints the ajv errors readably. This is the thing a human runs
  before dropping a file in the inbox.

## 6 · The link pass

`server/src/link.js`. Entirely deterministic — **no LLM, no heuristic merging.**
Runs after every ingest. Truncates and rebuilds `drift`.

**Ownership.** A node's `owner_repo` is the repo whose manifest declared it via
an owning edge: `db.owns`, `http.expose`, or `kafka.produce`. If several claim
it, the first by `first_seen` wins and a `multiple-owners` drift row is written.
If none do, `owner_repo` stays NULL.

**Orphan creation.** An edge may point at a node no manifest declared — that is
normal and expected, because the other end lives in a repo outside the scanned
set. Create the node with `orphan=1`, `kind` inferred from the id prefix
(`svc:`→service, `topic:`→kafka.topic, `db:`→database, `cache:`→cache,
`api:`→endpoint, `contract:`→contract, `ext:`→external) and `name` = the id's
value part.

**Drift findings.** Each writes a `drift` row:

| `kind` | Condition | Severity |
|---|---|---|
| `no-producer` | a `kafka.topic` with ≥1 consume edge and 0 produce edges | warn |
| `no-consumer` | a `kafka.topic` with ≥1 produce edge and 0 consume edges | info |
| `version-skew` | a contract with >1 distinct version in `contract_bindings` | warn |
| `shared-database` | a `database` written or owned by >1 distinct service | warn |
| `multiple-owners` | >1 repo claims ownership of one node | warn |
| `near-miss` | two ids of the same kind that normalise identically (lowercase, strip `._-`, strip a trailing `v<N>`) | warn |
| `orphan-endpoint` | an `endpoint` with `http.call` edges but no `http.expose` | info |
| `stale-evidence` | reserved for Phase 5; not produced in v1 | — |

**`near-miss` never auto-merges.** It reports a suspected duplicate and a human
decides. Auto-merging ids is how a map starts lying.

`data` holds whatever the UI needs to render the finding — for `version-skew`,
the list of `{service_id, version}`; for `shared-database`, the writing services.

## 7 · Search

FTS5, rebuilt on ingest. One row per node, per edge (with a description), and
per unresolved entry.

- `title` — the node's name, or `from → to` for an edge.
- `body` — id, description, kind, engine/path/contract type, owning repo, team,
  plus every evidence `file` path and `snippet`. **Indexing the snippets is the
  point**: searching `KafkaListener` or a table name has to find things.

`GET /api/search?q=&kind=&limit=` runs an FTS5 `MATCH`, ordered by `bm25()`,
returning `{subject_kind, subject_id, title, snippet, kind, repo}` with the
FTS5 `snippet()` highlight. Sanitise `q` — wrap bare terms in double quotes so
a user typing `payments.settled.v1` or `GET /v1/x` does not produce an FTS5
syntax error. A malformed query returns empty results, never a 500.

Also support a `kind:` prefix filter typed inline (`kind:topic settled`), parsed
off the front of the query.

## 8 · HTTP API

All under `/api`, all JSON, all ids as **query parameters**. Errors return
`{error: string}` with a sensible status.

| Method | Path | Returns |
|---|---|---|
| GET | `/api/status` | `{ready, counts:{services,topics,databases,caches,contracts,endpoints,externals,edges}, repos:[{repo,commit,scannedAt,ingestedAt,producer,status}], quarantined:n, drift:{kind:count}}` |
| GET | `/api/graph?focus=&depth=&kinds=&repos=&includeExternal=` | `{nodes:[…], edges:[…]}` — see below |
| GET | `/api/node?id=` | `{node, overrides, in:[edge…], out:[edge…], evidence:[…], bindings:[…], drift:[…], neighbours:[…]}` |
| GET | `/api/edge?id=` | `{edge, evidence:[…], from:node, to:node}` |
| GET | `/api/search?q=&kind=&limit=` | `{hits:[…]}` |
| GET | `/api/drift?kind=` | `{findings:[…]}` grouped by kind |
| GET | `/api/manifests` | ingest log, newest first, including quarantined rows with their errors |
| POST | `/api/ingest` | body = manifest JSON → `{ok, repo, counts}` or `{ok:false, errors}` |
| POST | `/api/ingest/sweep` | `{results:[{file, ok, errors?}]}` |
| PUT | `/api/override` | body `{subjectKind, subjectId, field, value}` |
| DELETE | `/api/override?subjectKind=&subjectId=&field=` | removes one |
| GET | `/api/repos` | contents of `repos.json` joined to last ingest per repo |
| GET | `/api/prompt?name=scan-pass1&repo=` | `{text}` — the prompt from `prompts/`, with `{{SCHEMA}}` and `{{REPO}}` substituted |

### `/api/graph` semantics

- `focus` — a node id. Omitted means the whole estate.
- `depth` — hops from `focus`. `1` = focus plus direct neighbours (**default**),
  `2` = two hops, `0` = everything.
- `kinds` — comma-separated node kinds to include. Default: all but `contract`
  (contracts clutter the default view; they are opt-in).
- `repos` — comma-separated repo filter.
- `includeExternal` — `false` hides `kind='external'` and `orphan=1` nodes.

Nodes come back with `{id, kind, name, description, engine, method, path, team,
ownerRepo, orphan, degree}`; edges with `{id, from, to, kind, contractId,
description, confidence}`. Apply `overrides` before returning. Omit nodes with
an `hidden` override unless `focus` is that node.

## 10 · Pages

### `/` — Map

The primary screen. A `FilterBar` across the top (same visual treatment as the
sibling's `ScopeBar`, see `reference/jira-reports/ScopeBar.tsx`):

- **Focus** — a `Picker` over all nodes, searchable. Empty = whole estate.
- **Depth** — segmented control: 1 / 2 / All. Disabled when focus is empty.
- **Show** — multi-select of node kinds, with counts.
- **Repos** — multi-select.
- **External** — toggle.

Below it, `MapCanvas` filling the remaining height. Right-hand inspector panel
(320px, collapsible) showing the selected node: name, kind, owning repo,
description, and its first three evidence citations, with a "Open details →"
link to `/node?id=`.

Single click selects and fills the inspector. Double click re-focuses the graph
on that node (sets `focus` and `depth=1`). The browser back button must undo a
re-focus, so focus/depth live in the query string.

### `/node?id=` — Node detail

Renders differently per `kind`, but always: header (name, kind badge, owning
repo, team), description with an inline edit that writes an override, and an
`EvidenceList`.

- **service** — four `DataGrid`s: Produces, Consumes, Calls, Called by. Plus
  databases and caches it touches, contracts it binds with versions, and any
  drift findings that name it.
- **kafka.topic** — **Producers** and **Consumers** grids side by side. This is
  the screen the whole project was asked for; make it the best one. Each row
  links to the service and shows the evidence file:line. Show the contract the
  topic carries and every binding version, flagging skew.
- **contract** — every service that binds it, with versions, sorted so a skew is
  obvious. Topics that carry it.
- **database / cache** — services that own, write and read it.
- **endpoint** — the exposing service and every caller.
- **external** — callers.

`EvidenceList` renders `repo · file:line` with the snippet in a `<code>` block,
monospace, using the existing `--surface-2` and `--border` tokens.

### `/search`

A single input, results grouped by subject kind, keyboard navigable (↑/↓/Enter).
Show the FTS5 highlight. Empty query shows the estate summary counts instead of
nothing. This page must feel instant — debounce 120ms, no spinner for <300ms.

### `/drift`

The findings from §6, grouped by kind, each expandable to the participating
nodes and their evidence. This page is how the map proves it is still honest;
give it real care, not a bare table. Empty state: "No drift detected across N
repos" — and mean it.

### `/scan`

The operator page. Three sections:

1. **Repositories** — the `repos.json` list with last-scanned commit and
   relative time, from `/api/repos`.
2. **Prompt** — a repo `Picker`, then the rendered pass-1 prompt in a
   scrollable `<pre>` with a **Copy** button. This is the thing a human pastes
   into Claude in the target repo.
3. **Inbox** — a file drop zone and a **Sweep inbox** button; the result of the
   last sweep, per file, with validation errors rendered readably.

### `/manifests`

The ingest log: repo, commit, producer, when, status, counts. Quarantined rows
expand to show the ajv errors with the offending JSON pointer. A re-ingest
button per row.

## 11 · Graph rendering

`@xyflow/react` for the canvas, `elkjs` for layout. **No force layout** — node
positions must be stable and reproducible so a service is in the same place on
every visit.

```js
// layout.ts
{
  'elk.algorithm': 'layered',
  'elk.direction': 'RIGHT',
  'elk.layered.spacing.nodeNodeBetweenLayers': '110',
  'elk.spacing.nodeNode': '48',
  'elk.layered.nodePlacement.strategy': 'NETWORK_SIMPLEX',
  'elk.layered.crossingMinimization.semiInteractive': 'true'
}
```

Run layout in a `useEffect` keyed on the node/edge id sets, not on every render.
Show the existing `.spinner` while it computes. Memoise: the same id set must
not re-layout.

Custom node components, one per kind, all built from the existing tokens:

| kind | shape | fill |
|---|---|---|
| service | rounded rect, 8px radius, bold label | `--series-1` |
| kafka.topic | pill, fully rounded | `--series-3` |
| database | rect with a cylinder glyph | `--series-4` |
| cache | rect with a cylinder glyph, dashed border | `--series-5` |
| endpoint | rect, monospace label | `--series-2` |
| contract | rect, dashed border | `--series-7` |
| external | rect, dashed border, muted | `--text-muted` |

Node fills are the token at ~14% alpha with a full-strength 1.5px border and
`--text-primary` label — not saturated blocks. An `orphan=1` node additionally
gets a dashed border and 70% opacity. The focused node gets a 2px `--accent`
ring.

Edge styling carries the semantics: solid for `http.*`, dashed for `kafka.*`,
dotted for `depends.on` and `topic.schema`, all in `--axis` at rest and
`--accent` when the edge touches the selected node. Arrow heads always point in
the direction data flows — remember `from` is always the service, so a
`kafka.consume` edge renders **topic → service**, reversed from its stored
direction. Get this right; it is the single easiest thing to get backwards.

Include React Flow's `<MiniMap>`, `<Controls>` and `<Background variant="dots">`,
themed with the CSS tokens so they work in dark mode. A graph of >150 nodes
should hide labels below 0.5 zoom.

## 15 · Gotchas and invariants

1. **Ids never go in a URL path.** Query parameters only. An id contains `:`,
   `/`, spaces and `{}`.
2. **`from` is always the service.** The renderer reverses the arrow for
   `kafka.consume` and `db.read`; the data never does.
3. **Contract versions are per service**, in `contract_bindings`, never on the
   `nodes` row. Putting them on the node destroys the skew finding.
4. **Overrides are never touched by ingest.** If a re-ingest can revert a human
   edit, the feature is broken no matter what the tests say.
5. **A quarantined manifest imports nothing.** No partial imports, ever.
6. **`near-miss` never auto-merges.**
7. **Evidence snippets are indexed for search.** That is most of the value of
   search; do not index only names.
8. **Empty states are real states.** No demo data leaking into an empty install,
   no placeholder rows.
9. **Layout is deterministic.** If a node moves between loads, the layout is
   wrong. No force simulation anywhere.
10. **Do not touch `theme.css` values.** They are a validated palette. Add new
    tokens if you need them; do not retune the existing ones.
11. The sibling project is a *reference*, not a dependency. Nothing in
    `reference/` is imported, and the folder is deleted in Phase 6.
